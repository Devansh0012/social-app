# Deploying Braventex to braventex.in

Stack: **Vercel** (web) + **Railway** (api) + **Neon** (Postgres) + **Cloudflare R2** (file storage) + **Resend** (email) + **GoDaddy** DNS.

Estimated cost: ~$0–10/mo on free tiers for low MVP traffic.

---

## Phase 0 — generate secrets (do this once)

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

You'll need **two** values:
- `JWT_ACCESS_SECRET`
- `JWT_REFRESH_SECRET`

Drop them into a scratch doc — you'll paste them into Railway in Phase 3.

---

## Phase 1 — Neon (Postgres)

1. Sign up at [neon.tech](https://neon.tech) → **Create project** `braventex`, region close to your users.
2. From the dashboard, copy two connection strings:
   - **Pooled** (the default one) → `DATABASE_URL`
   - **Direct** (toggle "Pooled connection: off") → `DIRECT_DATABASE_URL`

Save both.

---

## Phase 2 — Cloudflare R2 (file storage)

1. cloudflare.com → R2 → **Create bucket** `braventex-uploads`.
2. Bucket → **Settings** → **Public access** → "Allow Access". This gives you a `pub-...r2.dev` URL — copy it.
3. **Manage R2 API Tokens** → Create token with **Object Read & Write** scoped to that bucket. Save:
   - Access Key ID → `STORAGE_S3_ACCESS_KEY_ID`
   - Secret Access Key → `STORAGE_S3_SECRET_ACCESS_KEY`
   - Endpoint (looks like `https://<account>.r2.cloudflarestorage.com`) → `STORAGE_S3_ENDPOINT`
4. The public URL from step 2 → `STORAGE_PUBLIC_BASE_URL`.

Optional: bind a custom domain like `cdn.braventex.in` later (R2 → Settings → Custom Domains).

---

## Phase 3 — Resend (transactional email)

1. resend.com → **Add Domain** `braventex.in`.
2. Resend shows **3 DNS records** (SPF + DKIM + return-path). Copy them.
3. In a new tab: GoDaddy → **My Products → DNS for braventex.in** → add those records. Don't touch existing MX records (those keep your Professional Email inbox working).
4. Wait for Resend to mark the domain "verified" (usually <5 min).
5. **API Keys** → Create → save as `RESEND_API_KEY`.

---

## Phase 4 — Push your repo & deploy the API on Railway

> Prereq: code committed and pushed to GitHub.

1. railway.app → **New Project** → **Deploy from GitHub** → pick `social-app`.
2. Railway auto-detects `apps/api/Dockerfile` (we ship a `railway.json` that points at it).
3. **Settings → Service** → confirm:
   - Builder: **Dockerfile** at `apps/api/Dockerfile`
   - Pre-deploy: `npx prisma migrate deploy` (in `railway.json`)
   - Start: `node dist/server.js`
4. **Variables** — paste the following:

   ```
   NODE_ENV=production
   API_HOST=0.0.0.0
   API_PUBLIC_URL=https://api.braventex.in
   APP_PUBLIC_URL=https://braventex.in
   CORS_ORIGIN=https://braventex.in,https://www.braventex.in
   LOG_LEVEL=info

   DATABASE_URL=<neon pooled URL>
   DIRECT_DATABASE_URL=<neon direct URL>

   JWT_ACCESS_SECRET=<random 32B base64>
   JWT_REFRESH_SECRET=<random 32B base64>

   STORAGE_DRIVER=r2
   STORAGE_S3_BUCKET=braventex-uploads
   STORAGE_S3_REGION=auto
   STORAGE_S3_ENDPOINT=https://<account>.r2.cloudflarestorage.com
   STORAGE_S3_ACCESS_KEY_ID=<r2 access key>
   STORAGE_S3_SECRET_ACCESS_KEY=<r2 secret>
   STORAGE_PUBLIC_BASE_URL=https://pub-<id>.r2.dev

   RESEND_API_KEY=<resend key>
   EMAIL_FROM=Braventex <noreply@braventex.in>
   ```

5. Deploy. First deploy runs `prisma migrate deploy` automatically. Once the service is green, hit:
   ```
   https://<auto-generated>.up.railway.app/health
   ```
   You should see `{ "status": "ok" }`.

6. **Seed colleges + admin user** (once):
   ```bash
   railway link            # picks the project
   railway run --service=api pnpm --filter @braventex/api exec prisma db seed
   ```

7. **Settings → Networking → Public Networking → Add Custom Domain** → `api.braventex.in`. Railway shows you a **CNAME target** like `xyz.up.railway.app`. Save that — you'll need it in Phase 6.

---

## Phase 5 — Deploy the web app on Vercel

1. vercel.com → **Import Project** → pick `social-app`.
2. Project settings:
   - **Root directory**: `apps/web`
   - Framework: Next.js (auto-detected)
   - Install command: `pnpm install`
   - Build command: `pnpm build`
3. **Environment Variables** — add for *Production*:
   ```
   NEXT_PUBLIC_API_URL=https://api.braventex.in
   NEXT_PUBLIC_GRAPHQL_URL=https://api.braventex.in/graphql
   NEXT_PUBLIC_WS_URL=wss://api.braventex.in/ws
   ```
4. Deploy. Confirm it works at the auto-generated `braventex.vercel.app` URL (the API calls will fail until Phase 6 DNS lands).
5. **Settings → Domains** → add `braventex.in` and `www.braventex.in`. Vercel will show you the **DNS values to set** (an A record + a CNAME). Save those.

---

## Phase 6 — GoDaddy DNS for braventex.in

In **GoDaddy → My Products → DNS for braventex.in**, add the following. Keep your **MX records untouched** (Professional Email).

| Type | Name | Value | TTL |
|---|---|---|---|
| A | `@` | (Vercel-provided IP, usually `76.76.21.21`) | 600 |
| CNAME | `www` | `cname.vercel-dns.com` | 600 |
| CNAME | `api` | the Railway CNAME target from Phase 4 (e.g. `xyz.up.railway.app`) | 600 |
| TXT / CNAME (3 records) | (DKIM/SPF/return-path) | Resend-provided values (from Phase 3) | 3600 |

Verify propagation:
```bash
dig braventex.in
dig api.braventex.in
dig _resend._domainkey.braventex.in TXT
```

5–30 minutes is typical. SSL certs are issued automatically by Vercel & Railway once DNS resolves.

## Phase 7 — smoke test the whole loop

1. Open https://braventex.in — landing page renders, SSL is green.
2. `/signup` with a college email (or `@braventex.in` if you're using a seeded dev college). Confirm Resend dashboard shows a delivered email.
3. Click the verification link → `/onboarding`. Complete the flow.
4. `/feed` shows the empty state. Open a community, post, like, comment.
5. Open `/study-rooms` and start a room — confirm WS frames in the browser devtools (`Network → WS`).
6. Browser console should be empty of CORS or 401 errors.

## Phase 8 — recommended hardening (not blockers)

- **Sentry** (frontend & backend) — DSN as env var, `Sentry.init` in `app.ts` and `app/layout.tsx`.
- **Cloudflare** in front of `braventex.in` (proxy mode) for DDoS protection — works fine with Vercel.
- **Backup**: Neon Pro includes PITR; otherwise schedule `pg_dump` daily.
- **Billing alarms** on Railway (Project Settings → Usage).
- **Privacy + Terms** pages — add `/privacy` and `/terms` routes before launch.
- **Bigger rate limits** on `/graphql` and per-mutation rate limits on `signup` / `login`.
- **Custom R2 domain**: `cdn.braventex.in` → R2 bucket (faster + branded).

## Common gotchas

- **Verification email lands in spam** — wait 24h after DKIM is verified; SPF/DKIM/DMARC alignment takes a bit. Pre-warm by sending a few test emails first.
- **`wss://` upgrade fails** — confirm Railway's reverse proxy is not stripping `Upgrade` headers (it isn't by default, but if you use a custom CDN in front, check).
- **Prisma migration fails on Railway** with `connection pool` errors — use Neon's *direct* URL in `DIRECT_DATABASE_URL`. The pooled URL doesn't support some migration ops.
- **CORS still blocks** — `CORS_ORIGIN` must match the **exact origin** Vercel uses (https, no trailing slash, both apex and www if you allow both).
- **R2 access denied on uploads** — token must be scoped to the bucket and have **Object Write** (not just Read).
